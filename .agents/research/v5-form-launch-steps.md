# ArbCut form: steps before launch (6 Nov 2026)

The form posts to the JarvisWeb Cloudflare Worker `jarvisweb-proof-tracking` (`https://jarvisweb.lt/t/form`, `kind=site_inquiry`, `site=arbcut`). `arbcut` is already in the private `SITES` config with origins `https://arbcut.lt` and `https://www.arbcut.lt`. No move off Vercel is needed for the form. No live test has been run, by user instruction.

Checked read-only on 6 Nov: `matas@jarvisweb.lt` forwards to `jarvisworks.co@gmail.com`, which is already a verified destination. `aukstuminiai.darbai@yahoo.com` is not verified. The `arbcut.lt` zone is not in the Jarvisworks Cloudflare account.

**Update 11 Nov 2026 (Matas):** launch with the simple email-only form through the Worker (not Web3Forms). Sending to the phone is Offer 2, later. Turnstile is now optional: the live Worker checks it only for meselektra/vensland (`security.ts` `SECURITY_SITES`), so for `arbcut` steps 3–5 are optional hardening. Without `PUBLIC_TURNSTILE_SITE_KEY` the widget is not rendered and the build no longer fails. Required: steps 1, 2 and 6, plus the photo branch below if photos stay on.

**Update 11 Nov 2026, launch-ready with the live Worker:** `features.photoUpload: false` (the form says "Nuotraukas siųskite el. paštu" instead), and the private `/ivertinimas` message now requires a phone and has no email field, so neither depends on unmerged Worker branches. Checked read-only on 11 Nov: `SITES` already has `arbcut`; `allowed_destination_addresses` = jarvisworks.co, meselektra, vensland (no Yahoo yet); `FORM_SITE_RECIPIENTS` is not in the toml, so it is a Worker secret whose current value must be re-put whole with `arbcut` added (it cannot be read back).

Do in this order. Each step needs the user's word in the thread.

1. **Mantas's inbox.** Add `aukstuminiai.darbai@yahoo.com` under Email Routing, Destination Addresses. Cloudflare emails Mantas a link he must click.
2. **Worker config** (`~/Library/Application Support/JarvisWeb/wrangler-production.toml`): add the Yahoo address to `allowed_destination_addresses`, and add `"arbcut": ["aukstuminiai.darbai@yahoo.com", "jarvisworks.co@gmail.com"]` to the private `FORM_SITE_RECIPIENTS`. A missing route sends to the owner only, so this is a launch gate.
3. **Worker code** (JarvisCo `tracking/src/security.ts`, `index.ts`): Turnstile is limited to `meselektra` and `vensland`, and the README says not to add other clients to the config. Add `arbcut` to `SECURITY_SITES` and a `TURNSTILE_SECRET_ARBCUT` secret. Owner: Worker release owner, following the staged rollout in `tracking/README.md`.
4. **Turnstile widget.** Create it with hostnames `arbcut.lt` and `www.arbcut.lt`, set the secret on the Worker, and set `PUBLIC_TURNSTILE_SITE_KEY` in the site build. The production build fails on purpose without this key.
5. **Order.** Worker in `observe`, then deploy the site, then check it, then switch `arbcut` to `enforce`. Never enforce before the site is live.
6. **Live test.** One test submission, only when the user asks: check both inboxes, and that Yahoo does not file it as spam.

**Photos: launch gate.** Decision (user, 6 Nov): photos go to the inbox as email attachments. Each enquiry arrives as the normal text alert, then a second email with the photos, so a photo problem cannot affect the enquiry. The form sends them as repeated `files` (5 at most, 8 MiB total; large JPEG/PNG/WebP are shrunk to 2000 px in the browser). Tested against a local copy of the Worker: 4 photos stored, one read back byte-identical via `/t/files/<key>` with the owner token, and refused (401) without it.

Worker change: built and tested, not merged or deployed. JarvisCo branch `feat/form-email-attachments-20261106` (commit `c807791`, worktree `~/Work/Code projects/JarvisCo-worktrees/form-email-attachments-20261106`). It is opt-in, so other clients keep the plain alert. Codex reviewed two rounds; the final redesign answers round 2 but has not had its own independent review, so review it before merging. To turn it on: merge, deploy, and add `FORM_ATTACHMENT_SITES = '["arbcut"]'` to the private `wrangler-production.toml`. Encoding 2.5 MB took about 4 ms in local workerd; the account's plan and CPU limit could not be read, so check them. Until this is live the email shows only `Failų skaičius: N`, so do not launch the uploader without it: `features.photoUpload: false` in `src/data/site.js` removes it.

Limits to know: 5 forms a minute and 30 a day for this site. Delivery is best effort: the enquiry is stored even if the alert email fails, and the alert is not retried.
